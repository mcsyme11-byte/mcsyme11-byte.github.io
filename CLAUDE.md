# Instructions for Claude working in this repository

This is Malcolm Syme's public portfolio website (https://mcsyme11-byte.github.io/), maintained from the Claude project **"MS Projects Summery / Portfolio"**. It lists his past projects, current projects and ideas across all his GitHub repos.

## Standing rules

- **This site is public.** Never add a home or business street address, city, school name, age, PC names, file paths, callsigns or VATSIM IDs. Keep "Malcolm Syme", mcsyme11@gmail.com and his phone number +1 (403) 679-1495 (added at his request, Nov 16, 2026) as the credit and contact.
- **Never link to private repos** (Flight-Deck-Suite, formerly Syme-Flight-Suite, HotMic source, Simply-Aerospace-Archive, Airport-Scenery-Profile-Development-MSFS2024). Describe those projects instead; link only to public sites and public repos.
- **All content lives in `data/projects.js`.** Change the page structure only when Malcolm asks.
- **Extra pages** (`about/`, `experience/`, `ideas/`, `patches/`, `alpha/`, `studies/`, `flights/`, `lessons/`, `admissions/`) are generated by `python3 dev/build_pages.py` (text there and in `dev/pages_extra.py`) and filled by `assets/pages.js` and `assets/media.js`; edit the generator, never the generated HTML. Case studies come from `dev/build_cases.py`. Its `V` and `dev/build_cases.py`'s `V` carry the same `?v=` tag as `index.html`.
- **The footer is identical on every page** (Malcolm, Nov 18, 2026): the same seal, contact, five columns, patches and credit line everywhere, with nothing left out on any page.
- **One footer, from one place:** `dev/shared.py` holds the page order and builds the footer for every page: the "Keep exploring" directory of the other pages (Malcolm's choice, Nov 18, 2026, replacing a Previous / Next bar), the seal, the remaining links, the six project patches. A new page is added to `PAGES` and `ABOUT` there once. Pages carry no boxed "next" links above the footer; a single plain link under a section is fine.
- **Formatting sweep before publishing** (Malcolm, Nov 18, 2026): check every page at phone, tablet and desktop widths (390, 600, 820, 1024, 1100, 1200, 1440 px) for sideways overflow, text running off screen, overlapping chart labels and broken images, and look at the screenshots. The menu folds into its button below 1060 px.
- **Class names:** before adding a style, check the name is not already used (`.tip` and `.rev` clashed once and hid content on phones).
- **Résumé details stay generic** (Malcolm's résumé was used as a source on Nov 18, 2026): roles, dates, duties and certifications only. Never name the town, postal code, school, grade, clubs or employers; write "Local restaurant", "Youth cross-country ski program", "Family business".
- **Write for visitors, never to Malcolm** (his rule, Nov 18, 2026): every word on the site is in his voice, addressed to a visitor. No notes about the update itself ("there's more than one page now", "four new pages"), no working rules between Malcolm and Claude ("nothing is built until I say go", "I approve the mock-up"). Before publishing, read every new line and ask who it is talking to.
- **Project Alpha** (`alpha/`) is a first revision and says so. Show only calculations that have been re-checked; say the motor, recovery sizes and launch plan are still being sorted out; never publish the launch site, purchasing details, the propellant mix or ejection-charge amounts. Update the build log when Malcolm reports progress.
- **Photos** are re-encoded without EXIF (drone photos carry GPS) and named and captioned without place names.
- **Build activity** (`data/activity.js`) is rebuilt with `dev/build_activity.py` when the site is updated; automatic commits are left out and only counts are published.
- **Counts must match the lists:** "seven apps", "nine tools", "30 ideas", "nine lessons", "five case studies" and the stats tiles are re-counted from `data/projects.js` and the project repos whenever a project changes.
- **After every change, bump the `?v=` version on the CSS and script links in `index.html`** (for example `?v=20261116d` → `?v=20261117a`), so browsers load the new files instead of an old cached copy.
- **Performance:** nothing may run every frame while scrolling. Animate only `transform` and `opacity`; no `backdrop-filter`, no animated `box-shadow`, no scroll or pointermove handlers outside one requestAnimationFrame. Re-check smoothness after visual changes.
- **Keep it current:** when a project's version, status or highlights change in its own repo, update its entry here and the `updated` date. Add a dated line to `news` in `data/projects.js` for anything that ships.
- **Logos come from the project repos.** Each project with its own repo chooses its logo there (`brand/` in that repo); this site copies the final files into `brand/patches/` and sets `patchImage`, `markImage` and `patchMin` from that project's own size guide. When checking projects for updates, check their `brand/` folders too, and pull any change. Only projects without a repo, and ideas, keep the patches drawn by `assets/patches.js`.
- **When a logo changes, remake its thumbnail** in `brand/patches/thumb/` (232 px PNG from the project's 1024 px PNG). **When an idea becomes real,** remove it from the ideas and add it to its project's entry.
- **The Journey route** reads its position fresh on every update; never cache page positions at load, because content above it arrives late.
- **Case studies** (`case/*.html`) must stay factual: every statement comes from the project's own `docs/HISTORY.md` or CHANGELOG. No PC hardware, paths or personal setup details.
- **Accuracy:** only state facts that are true and checkable in the repos or confirmed by Malcolm. Never invent achievements.
- **Look:** follow the shared "old money" design (navy, brass and cream, serif type), kept modern; it must work on phones, tablets and PCs. Big visual changes start as a proposal Malcolm approves.
- When Malcolm asks a question, answer it only; change nothing until he says go.
- Before calling a change done, look at it at desktop and phone widths and check the browser console for errors.
