01The problem

I wanted to learn how real space data works: where it comes from, how messy it is, and how to show it honestly. NASA and ESA publish a huge amount for free, but it is spread across dozens of services, each with its own format, limits and rules.

The plan was three learning projects in one public website, each one building skills the next would use: an asteroid tracker, an image explorer, then a study of Mars weather data.

02What I built

Asteroid Tracker

The asteroids passing Earth, a page and orbit diagram for each, a turnable map of all 43,000, and which ones a spacecraft could reach.

Mars Data

Weather measured by Curiosity and Perseverance, cleaned by written rules and charted by Mars day, season and hour.

Image Explorer

The Earth from orbit on any day since 2000, on a globe inside the real sky, plus NASA's and ESA's picture libraries.

Orbit Watch

Satellites and space junk on a live globe, the closest predicted passes, a collision calculator and a model of the Kessler syndrome.

Space Weather and Exoplanets

What the Sun is doing now, and how planets around other stars are found, shown with real measurements.

Planetary Maps and more

Maps of the Moon and Mars with every landing site, plus Sky Finder and the spacecraft map.

The last four tools are Orbit & Space Watch. Each started as a line on my list of project ideas, got a written brief and a mock-up I approved, and went live in November 2026.

03Key decisions

Check the live service before building on it

JPL's close-approach service can't be called from a web page, so the year view reads a file that GitHub refreshes every day. NASA's fire layers only work in one map projection, so that set the projection for the whole map.

Visitors never need a key

No API key is ever written into the public repository. Data that needs one is copied by scheduled jobs on GitHub, using secrets only GitHub can read.

NASA first, ESA beside it, everything credited

ESA's data was added where it helps, with NASA as the main source. Every page says which agency each number or picture comes from, and that the project isn't endorsed by either.

Clean data by written rules

Mars weather isn't tidy. The rules for cleaning it are written down as documents, and the row counts are checked against NASA's own labels.

Change the plan when the mock-up disappoints

The first Image Explorer mock-up was a daily satellite map, with gaps between passes and no fine detail. I asked for a globe with pictures pinned to places on Earth and in the sky instead, and kept the daily map for following fires and storms.

One standard for automatic updates

Every data job keeps the previous file when a source fails, and a daily health check reports problems in one place.

04What went wrong

Real data and real services kept surprising me. Each of these was found by checking, not by assuming:

  • Choppy frames when zoomed in. Lines that ran far off screen were still being drawn dash by dash. Cutting each line to the visible area fixed it.
  • Famous close passes looked wrong. Simple orbit maths can't show them, because Earth's pull bends the asteroid's path. Precise positions from NASA/JPL Horizons are used instead.
  • A marker in the wrong place. A check of the hand-listed sky positions found one real mistake: Rho Ophiuchi sat on the star, not on the cloud named after it.
  • Servers that say no. JPL refuses an address after several hundred quick requests, so the monthly job asks one question a second.
  • Formats that change. Objects catalogued since July 2026 no longer appear in the old orbit format, so Orbit Watch reads the newer one.
The rule it created

Check facts about the data. Every address, field and limit is confirmed against the agency's current documentation, and against the live service, before anything is built on it.

05How the work is done

  • One chat per tool, each working inside its own folder, with a general chat for the shared files and one chat that owns every scheduled data job.
  • Mock-ups first. New pages start as a mock-up I approve.
  • Shared parts only. Every page is built from the same components, and automatic checks on GitHub refuse a page that breaks the rules.
  • Measured, not guessed. Smoothness was measured throughout; two changes took the solar system map to 60 frames a second.

06What I learned

Real data is never as clean as the examples in a tutorial, and showing it honestly matters as much as showing it beautifully: saying where a number comes from, what it leaves out, and how sure anyone can be. I also learned how fast an idea can become real when the brief is clear, since Orbit & Space Watch went from my ideas list to four live tools in days.
