How I built Hot Mic

Building a free, private dictation app that's as smart as a cloud assistant, works for people with low vision, and never sends a word of audio off the computer.

01The problem

I wanted to talk instead of type, in any app on Windows: Word, websites, chat apps, anything with a text box. Windows' own voice typing is literal; it doesn't clean up speech the way a modern AI assistant does. And I wanted it to help people for whom typing is hard, including people with low vision.

The bar I set: as smart as Claude's own voice input, free to run, and a single file that installs on any PC.

02Research first

  • Free local dictation apps already existed, but none was built around low vision.
  • NVIDIA's Parakeet was the most accurate free English speech model, and fast even without a graphics card.
  • A tiny model trained only for dictation clean-up could match a much bigger one, and leave correct text alone.
  • Most dictation apps paste carelessly: dictations leak into clipboard history, text gets lost silently, or an old clipboard gets pasted by mistake. Hot Mic does it properly.

03Key decisions

Everything on the computer

No paid cloud AI: speech recognition and smart clean-up both run locally. Privacy and cost stop being questions.

Accessibility first

Sound cues, a large high-contrast indicator, read-back, full keyboard control, screen readers and Windows contrast themes. Everything works without reading small text.

The name and the key

“Hot Mic” is a radio term: the mic is live. Press F9 to start, F9 to stop, changeable in Settings.

Never let speed cost accuracy

To go faster, Hot Mic skips the AI when there's nothing to fix, but it “can't start making mistakes”. A build check runs the real AI on a list of dictations: wherever Hot Mic would skip, the AI must give exactly the same text. The first run found 2 differences (grammar slips like “I seen”), so a grammar check was added. Now 137 of 176 skip, and none differ.

04What went wrong

“Not everyone has a proper mic, so it needs to work without it.”

Version 0.3 still struggled with Bluetooth headphones, which sound muffled in call mode. Instead of telling people to buy a microphone, Hot Mic 0.4 learned to notice a muffled mic and ask a second, tougher speech model (Whisper) to listen too, while a Performance setting steps everything down so a flight sim or game always comes first.

Other real bugs reviewers caught before release: “squawk one zero zero zero” turning into “10”, “Boeing seven thirty seven” being read as a time, and a version label that said 0.5.1 on 0.5.2, which made a working update look broken.

The rule it created

Tests checked what the app does, never what version it shows. Now there's a release checklist followed step by step for every version, and the first-start build test fails if the app shows the wrong version.

05How it's tested

  • An independent review before every install. The first build's review found 15 problems, all fixed before the code was even pushed.
  • Real pastes on a real Windows machine on every build: a long text, a slow app, a lost focus, a closed window.
  • The real speech model and AI on spoken test sentences before every release.
  • Automatic updates that never install while a game is running.

06What I learned

Accessibility changes every decision, from how loud a sound cue is to how big the indicator gets when Windows' text size is set to 160 %. And the best fixes came from using the app myself every day: almost every version started with something I noticed while actually talking to it.
