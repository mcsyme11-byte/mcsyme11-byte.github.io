How I built Flight Deck Suite

01The problem

I fly Microsoft Flight Simulator 2024 on VATSIM, the online network with real air traffic controllers. Two things were missing:

  • A real logbook that records every flight by itself, with a landing rate I can trust.
  • Freedom from the desk. On a long flight there was no way to watch the flight, hear ATC or react to a problem without sitting at the PC.

02What I built

It started as two separate apps and grew into one family:

Squawk

A vPilot plugin and iPhone/iPad app: ATC messages, the transponder, a live map and alerts.

Logbook

Logs every flight automatically, with landing rate, runway, crab angle and a grade, plus a full logbook website.

Playback

Landing replays flown by the sim itself, with screenshots and video clips.

Ramp

Parks realistic airliners on empty gates, sized to each stand and grouped by airline.

Vantage

Saved camera views and added sounds like runway rumble and touchdowns.

Hangar + Manager

A read-only add-on finder, and one app that installs and updates everything.

Everything runs on the pilot's own PC. The phone reaches it through a private Tailscale network, so there's no cloud server.

03Key decisions

Make it trustworthy before making it bigger

Real flights showed time in the sim's menus counting as flight time, and a stutter could cut a long flight in half. I rebuilt how sessions work so menus, pauses and data gaps are understood, using one SimConnect request instead of 25.

Grade landings by aircraft class

−250 fpm feels very different in an A320 and an A350, so single-aisle, light, regional, wide-body and very large aircraft each got their own limits. It was the first change to the grades since version 1.0.

Keep sharing physically separate from control

The public “Share my flight” page runs as a separate web server with no route to any control, and it refuses to go live if the control app were ever public. It shows a callsign only, never a name.

No hand-made airport profiles for Ramp

Each improvement goes into the rules, so it helps every airport. The airline mix comes from open ADS-B flight data.

Rename by copying and checking, never in place

When the suite was renamed, every folder was copied, each file checked against the original with SHA-256, and only then were shortcuts switched. The old folders stayed until I deleted them.

04What went wrong

“With Vantage 0.1.0 connected, the sim stopped twice, and MSFS's Safe Mode then switched every Community add-on off.”

That was the worst day of the project (Oct 29, 2026). We probed every request one at a time and all of them passed. The likeliest cause was timing: asking the sim for too much while the flight was still loading.

The rule it created

Nothing that talks to the sim reaches the PC untried. Every SimConnect request now runs first in a small test program at the gate, an app's first run is a careful test with the log watched (never a real flight), and an app that loses the sim stops and waits instead of reconnecting by itself. Vantage 0.1.1 then passed its first run and a 12-hour soak test.

05How the work is done

  • Plan first, build on “go”. Questions get answered before anything changes.
  • Never touch a flight in progress. Updates are installed only after landing.
  • Tested like a product: a fake vPilot and a fake Logbook for every build, hundreds of automated checks, and layout sweeps at iPhone, iPad and desktop sizes.
  • Independent review for bigger releases, checking security and correctness before shipping.
  • Declined ideas are written down so they aren't proposed again. Saying no is part of the design.

06What I learned

The hardest part wasn't writing features. It was making them trustworthy: numbers that match across every page, tools that never put the sim at risk, and a release process strict enough that a mistake can't slip through. Working with AI made building fast; my job was setting the goals, testing on real flights and deciding what was good enough to ship.
